# Critical Gate Guide

Instructions for Layer 2 Critical Gate (`review_host`) to evaluate, filter, and gate Layer 3 Reviewer feedback before mutating Directive Artifacts (DA).

## 1. Core Evaluation Principles

1. **Evidence over Assertion**: Reject reviewer feedback lacking concrete line/section citations, codebase symbol proof, or sandbox verification.
2. **Zero Sycophancy**: Reject speculative or over-engineered suggestions lacking concrete necessity.
3. **Scope Boundary Protection**: Reject unrequested features, premature refactorings, or unnecessary abstractions outside user criteria (*Protection Exception: End-to-End Parameter Seams, Orthogonal Governance Decoupling, Placement Altitude, and Scale Invariance MUST be accepted as valid structural requirements*).
4. **Clean Integration**: Convert accepted feedback into native specification requirements without meta-tags or reviewer references. Integrate verified code remediations, concrete signatures, and schemas alongside testable Acceptance Criteria.
5. **Ground-Truth Verification**: Reject feedback that introduces theoretical error classes, fail-fast deserialization barriers, or breaking contract changes on external ingress modules unless existing code and tests support that invariant without regression.
6. **Dependency Lineage & Boundary Protection**:
   - **ACCEPT** findings where the target DA contradicts or drifts from an `Upstream` DA schema/seam (*Spec Drift*), or duplicates responsibilities belonging to an `Upstream` DA (*Spec Bloat*).
   - **GATE FOR REMOVAL** findings where a reviewer claims unreadiness or missing files on disk explicitly scheduled in an unimplemented `Upstream` DA (*False-Positive Upstream Unreadiness*), or demands tightly coupling the target DA to future `Downstream` epics (*Premature Downstream Coupling*).
7. **Reviewer-Driven Fix Refinement & Gating (Strict Host Suggestion Ban)**: When a reported defect contains ungrounded code snippets, cites non-existent APIs, lacks Ground-Truth/Macro Flow proof, breaks boundary contract symmetry, introduces cross-section contradictions, conflicts with a higher-priority intra-tier remediation, or is invalid, Host MUST NOT rewrite the snippet, invent boundary counterparts, or suggest alternative code in `<Role>_Gated_Issues.md`. Host gates the issue requiring the reviewer to refine, remove, or prove it.
8. **Miss-Probability Gate over Implementation Trivia**: Evaluate findings assuming a headless AI implementer writing production code and tests strictly against ticket Acceptance Criteria in CI without unscripted browser/GUI operation (and writing ONLY tests explicitly mandated by Acceptance Criteria, never unprompted exploratory/adversarial tests). Accept as blocking defects ONLY issues that (a) would be silently missed in implementation (wrong results, numerical drift, race conditions, self-fulfilling unit tests), or (b) produce visible errors whose generalized fix across the class is not obvious without domain/architectural insight. If an issue produces an immediate compiler/stack-trace/assertion error AND the generalized fix is obvious across all instances, gate for reclassification to Suggestion or removal (`Obvious Implementation Signal`).
9. **Technical Impasse & Grounded Infeasibility Verification**: When a reviewer reports `STATUS: INFEASIBLE`, verify that the impasse is grounded in concrete technical evidence (sandbox restriction, protocol header, missing external capability, hardware ceiling). Gate speculative refusals where a standard seam or configuration resolves the issue (`Ungrounded Infeasibility Claim`). If verified, halt round with `PLAN_INFEASIBLE` and zero DA mutations.
10. **Strict Enforcement of Fail-Fast Boundary Invariant**: Reject reviewer feedback demanding defensive cascading fallbacks (`?? default`), heuristic property sniffing (`if ('x' in obj)`), or synthetic defaults inside internal domain logic. Postel's Law applies strictly to external ingress boundaries; internal core logic MUST fail fast on invariant violations.
11. **Feature Flag & Telemetry Lifecycle Governance**: Reject feature flags lacking archetype classification (`Ephemeral Release/Experiment` vs `Permanent Ops/Kill-Switch/Permission`), owner, relative lifespan (`TTL <= 30d post-rollout`) + removal trigger condition, deletion Acceptance Criterion, or strategy seam isolation. Reject unguarded debug logging or per-iteration spans inside hot-path loops.
12. **Configuration Modernization over Indefinite Toleration**: Reject dual-format configuration loaders, backward-compatibility wrapper shims, or permissive schemas (`.passthrough()`, `extra = 'allow'`) on internal paths. Require staging configuration file, environment contract, and test fixture modernization as a prerequisite structural task ($S$) before feature logic ($B$).
13. **Event Transparency over Propagation Suppression**: Reject `event.stopPropagation()` and `event.stopImmediatePropagation()`. Inter-component event coordination for nested controls must preserve event bubbling to `document` listeners via: (a) **Parent Target Filtering** (`event.target.closest('button, a, input, select, textarea, [role="button"], [data-interactive]')` ignored by parent container handler — mandatory when children include native checkboxes, radio inputs, links, or submit buttons so browser default actions are not canceled), OR (b) **Preventable Event Contracts** (`event.preventDefault()` with `event.defaultPrevented` validation) on custom non-native `type="button"` actions.
14. **Specification Atomicity over Monolithic Acceptance Criteria**: Reject compound acceptance criteria combining multiple viewport sizes, interaction branches, or async states that cannot be independently asserted by a single test run. Enforce decomposition into single-responsibility Given-When-Then criteria or state matrices.
15. **Upstream Ingress Traversal over Callee Masking**: Reject addressing unhandled edge cases by inserting defensive checks, null-guards, or try-catch fallbacks inside internal leaf callees/helpers. Trace invalid payloads upstream and block them at the highest viable caller or ingress boundary.
16. **Zero Tolerance for Technical Debt**: Reject proposals that accept architectural violations or technical debt simply because they function without runtime errors.
17. **Cohesive Locality over Complexity De-nesting**: Reject demanding that a function or module be split solely for line count, deep nesting, or branch complexity if all logic serves one cohesive task. Splitting is valid ONLY to: (1) separate mixed concerns (e.g. I/O from domain logic), (2) isolate independent failure domains, or (3) establish a testable seam.
18. **In-Memory State Normalization & Single Source of Truth**: ACCEPT findings eliminating denormalized duplicated entity state (`byId`/`allIds`) or replacing persisted derived state with pure selectors. GATE FOR REMOVAL findings demanding normalization of tiny, read-only isolated collections ($<10$ elements).
19. **Discriminated State Invariants over Boolean Flag Soup**: ACCEPT findings replacing mutually exclusive multi-boolean lifecycle flags with Discriminated Unions / State Machines. GATE FOR REMOVAL findings demanding state machines for trivial, independent binary toggles (e.g. `isMuted` and `isDarkTheme`).
20. **Algorithmic Collection Topology Enforcement**: ACCEPT findings replacing hot-path $O(N)$ linear array scans ($>50$ elements) or `Array.shift()` queues with `Map`, `Set`, `Trie`, or `Ring Buffer`. GATE FOR REMOVAL findings demanding complex trees (Tries, B-Trees) on tiny, fixed-size collections.
21. **Boundary Ingress Parsing over Primitive Obsession**: ACCEPT findings requiring strict boundary schema parsing into immutable domain types/Value Objects ("Parse, Don't Validate") and eliminating internal fallback sniffing.
22. **Operational Continuity Alignment**:
    - `CONTINUOUS_OPERATION` (default): ACCEPT findings enforcing vertical tracer-bullet slicing, zero-downtime $N$ & $N+1$ deployment phasing, expand-contract DDL, and operational readiness at every ticket.
    - `NON_CONTINUOUS_OPERATION` (tag `!NC`): GATE FOR REMOVAL feedback demanding vertical UI-to-DB slicing on early horizontal foundation milestones or temporary 24/7 dual-write/expand-contract shims. ACCEPT findings demanding **sequential schema migration scripts/runners ($V_1 \to V_2$) with zero data loss** (allowing single-step atomic cutover DDL inside the migration script), headless atomic tests on every ticket, and full system cutover + bootable verification + legacy decommissioning at the terminal milestone.
    - `NON_CONTINUOUS_INTERMEDIATE` (tag `!NC0` / `!NCI`): GATE FOR REMOVAL feedback demanding application bootability, UI cutovers, runtime launchers, or migration runners during OR after the epic. Enforce headless contract verification and downstream handoff integrity only.
23. **Plan-to-Modular-Epic Decomposition Alignment**: ACCEPT `DECOMPOSE_PLAN_TO_PRD_AND_TICKETS` when a single-file plan bundles 2+ discrete deliverables requiring staged, sequential verification gates. GATE FOR REMOVAL when decomposing a single cohesive deliverable verifiable by a single test run.
24. **Application vs. Library/SDK Archetype Boundary**: When the target DA is a reusable Library, SDK, or shared Package (rather than a standalone Application/Service), ACCEPT findings enforcing zero import-time side effects (`sideEffects: false`), explicit `"exports"` subpath encapsulation, `peerDependencies` singleton isolation, Bring-Your-Own-Logger (`NoOpLogger` default), API-only OpenTelemetry (`@opentelemetry/api`), `.dispose()` / `AbortSignal` listener cleanup, and programmatic `SdkError` codes. GATE FOR REMOVAL (`False-Positive Application Rule on Library/SDK`) any reviewer finding that demands global process signal handlers (`SIGTERM`/`SIGINT`/`uncaughtException`), `process.exit()` calls, direct `stdout`/`stderr`/file logging, `/healthz` HTTP endpoints, or implicit `process.env` reads inside a Library/SDK.

## 2. Triage Matrix

| Reviewer Finding Category | Gate Criterion | Action |
| :--- | :--- | :--- |
| **Architectural Invalidation** | Design reduces complexity, removes bottlenecks, or fixes contract breaks. | **ACCEPT**: Stage for Step 7 DA mutation. Invalidate downstream tiers. |
| **Lineage Contract Drift** | Target DA contradicts data models, types, or seams defined in an `Upstream` DA. | **ACCEPT**: Align target DA with upstream contracts. Invalidate downstream tiers. |
| **Lineage Spec Bloat** | Target DA duplicates or re-implements mechanisms governed by an `Upstream` DA. | **ACCEPT**: Remove duplicated scope and delegate to upstream DA. Invalidate downstream tiers. |
| **Progress / Roadmap Invalidation** | Monolithic ticket blocks incremental delivery, forward/circular ticket dependency, or phase boundary leak. | **ACCEPT**: Apply ticket splitting/re-ordering or scope isolation. Invalidate downstream tiers. |
| **Missing Edge Case / Safety** | Unhandled empty state, async/multithreaded race condition, filesystem/lock hazard, security flaw, or data corruption path. | **ACCEPT**: Add concrete guard requirement at appropriate boundary in target DA. |
| **Codebase Unreadiness** | Dependency missing, target file missing/locked, module/bundler resolution mismatch, or API contract mismatch. | **ACCEPT**: Add prerequisite task step to target DA. |
| **Schema / Migration Breakage** | Missing migration script/runner ($V_1 \to V_2$), incompatible JSON payload, unbatched table lock, missing rollback/backup, or ACID violation. | **ACCEPT**: Add migration safety requirement to target DA. Invalidate downstream tiers. |
| **Untestable Design / Missing Seams** | Tightly coupled globals/clocks, tautological/self-fulfilling tests, unvalidated drifting mocks, flaky sleeps, or missing verification coverage. | **ACCEPT**: Add test seam or verification requirement to target DA. Invalidate downstream tiers. |
| **Performance & Resource Leaks** | $O(N^2)$ hot-path loop, N+1 queries, unbatched SQLite/IPC writes, synchronous event-loop blocking, unclosed handles, unbounded memory cache, or rigid wall-clock stream timeout. | **ACCEPT**: Add optimization, batching, or resource cleanup requirement to target DA. |
| **Unobservable Operational Path** | Missing contextual telemetry/error `cause` in catch blocks, unredacted secrets/PII, CLI `stdout` pollution, unbounded client logs, high-cardinality metric labels, or missing kill-switch. | **ACCEPT**: Add telemetry/flag requirement to target DA. |
| **UX Friction, Raw Emoji & Unlabeled Icons** | UI element adds user friction, duplicates existing component, specifies raw emoji characters instead of vector SVG icons, uses icon-only controls for ambiguous domain actions without text, or omits accessible name/tooltip on canonical icon-only controls. | **ACCEPT**: Simplify/remove redundant elements, enforce vector SVG icons, mandate `aria-label` + tooltip on canonical icon-only controls, and require explicit text labels for domain actions. |
| **Representable Illegal State / Boolean Soup** | Lifecycle or async operation modeled via independent boolean flags allowing impossible states. | **ACCEPT**: Mandate Discriminated Union / State Machine types in target DA. Invalidate downstream tiers. |
| **Denormalized In-Memory State Drift** | In-memory store or cache duplicates entity records or persists derived state. | **ACCEPT**: Mandate normalized entity storage (`byId`/`allIds`) and pure derived selectors. Invalidate downstream tiers. |
| **Pathological Collection Choice** | Execution path specifies $O(N)$ linear array scans ($>50$ items) for key lookups/membership in hot paths, or uses `Array.shift()` for sliding windows. | **ACCEPT**: Mandate `Map`, `Set`, `Ring Buffer`, or `Trie` in target DA. Invalidate downstream tiers. |
| **Primitive Obsession in Domain Core** | Core business logic passes raw strings/numbers for critical domain identifiers, currencies, or units without invariant-enforcing Value Objects. | **ACCEPT**: Mandate branded types or Value Objects with smart constructors in target DA. Invalidate downstream tiers. |
| **Ingress Parsing Membrane Violation** | Untrusted external data accepted as loose dicts without boundary parsing, or internal functions contain defensive property sniffing and fallbacks. | **ACCEPT**: Mandate boundary schema parser (Zod/Pydantic) and eliminate internal fallback sniffing. Invalidate downstream tiers. |
| **Missing Terminal Cutover (Non-Continuous)** | In `NON_CONTINUOUS_OPERATION` (`!NC`), terminal milestone lacks full system cutover, migration script execution, bootable verification, or legacy decommissioning. | **ACCEPT**: Mandate complete cutover and bootable verification in terminal ticket. Invalidate downstream tiers. |
| **Big-Bang Integration Risk (Non-Continuous)** | In `NON_CONTINUOUS_OPERATION` or `NON_CONTINUOUS_INTERMEDIATE`, ticket omits headless verification tests, accumulating unverified code across milestones. | **ACCEPT**: Mandate automated headless verification tests or harness in target ticket. Invalidate downstream tiers. |
| **Multi-Gate Monolithic Plan** | Single-file plan bundles 2+ discrete deliverables requiring staged, sequential verification gates. | **ACCEPT**: Apply `DECOMPOSE_PLAN_TO_PRD_AND_TICKETS` during Step 7 per Principle 23. |
| **Library Host-Hijacking / Package Encapsulation Breach** | Library/SDK registers `SIGTERM`/`uncaughtException`, calls `process.exit()`, writes to `stdout`/`stderr`, reads `process.env` at import time, omits `package.json` `"exports"` encapsulation, bundles shared host singletons in `dependencies` instead of `peerDependencies`, or leaks `AbortSignal` listeners. | **ACCEPT**: Stage library isolation and packaging fixes in target DA. Invalidate downstream tiers. |
| **Non-Idempotent Retry / Unbounded Concurrency Hazard** | Execution path auto-retries non-idempotent `POST` mutations without a stable pre-loop `Idempotency-Key`, or runs unbounded `Promise.all(items.map(...))` over dynamic I/O collections. | **ACCEPT**: Mandate pre-loop `Idempotency-Key` and bounded concurrency pool/semaphore in target DA. |
| **Technical Impasse / Platform Infeasibility** | Reviewer proves a requirement is technically impossible (sandbox restriction, protocol block, physical bound) with zero viable in-scope fixes. | **ACCEPT AS IMPASSE**: Escalate to `PLAN_INFEASIBLE` immediately. Do NOT mutate DA. Cancel downstream tiers and conclude round. |
| **Ungrounded Fix Proposal** | Primary defect is valid, but proposed fix cites non-existent APIs, creates ordering/scoping defects, prescribes unverified magic-pixel CSS geometry or invented design tokens, forces root light-theme tokens on fixed dark surfaces, uses native HTML `disabled` on focused async controls, or lacks Ground-Truth/Macro Flow proof. | **GATE**: Demand reviewer refinement in `<Role>_Gated_Issues.md`. |
| **Asymmetric Boundary Contract** | Primary defect is valid, but proposed remediation modifies an internal boundary while omitting synchronized update for caller, listener, or shared types. | **GATE**: Demand reviewer completion of all boundary endpoints in `<Role>_Gated_Issues.md`. |
| **Cross-Section Contradiction** | Primary defect is valid, but proposed remediation contradicts existing assertions in `Verification Plan` or dependent sections without synchronizing them. | **GATE**: Demand reviewer alignment across dependent sections in `<Role>_Gated_Issues.md`. |
| **Inter-Role Remediation Conflict** | Two reviewers in the active tier batch propose mutually incompatible remediations for the same section or contract. | **GATE**: Apply §3 Conflict Resolution Precedence and demand the lower-precedence role align its remediation in `<Role>_Gated_Issues.md`. |
| **Ungrounded Infeasibility Claim** | Reviewer reports `STATUS: INFEASIBLE` without concrete empirical proof where a standard seam or configuration resolves the issue. | **GATE**: Demand reviewer convert to `STATUS: REVISIONS NEEDED` with verified fix, substantiate with empirical proof, or remove. |
| **Ad-Hoc Runtime Migration Bloat** | Reviewer proposes solving schema evolution via heuristic property sniffing in loaders, transient config flags, or migration logic inside UI/renderers. | **GATE FOR REFINEMENT**: Reject runtime fallbacks. Demand an isolated, sequential schema version runner ($V_1 \to V_2$) staged as step $S$ in the DA. |
| **Invented Protocol Verdict** | Reviewer returns a non-standard verdict (`STATUS: BLOCKED_*`) or demands halting workflow to spawn an external epic for basic scaffolding. | **GATE FOR REFINEMENT**: Instruct reviewer to return standard `STATUS: REVISIONS NEEDED` and stage scaffolding as step $S$ inside the DA. |
| **Defensive Fallback Bloat (Internal Core)** | Reviewer proposes cascading fallbacks (`?? default`), synthetic defaults, or property sniffing on internal core domain paths. | **GATE FOR REFINEMENT / REMOVAL**: Enforce boundary schema parsing at external ingress and fail-fast contracts on internal paths. |
| **Ambient Fault Masking / Silent Swallowing** | Reviewer proposes empty catch blocks, unchecked promise discard, or ambient fallback branching that conceals runtime errors. | **GATE FOR REFINEMENT**: Demand explicit error propagation, structured error logging with `cause`, or fail-fast boundaries. |
| **Ad-Hoc Runtime Flag Bloat** | Reviewer proposes feature flags without archetype classification, owner, relative TTL (`<= 30d post-rollout`) + removal condition, deletion test criterion, or scatters flags in domain core. | **GATE FOR REFINEMENT**: Demand toggle taxonomy, owner, relative TTL + removal condition, deletion criterion, and strategy seam isolation. |
| **Hot-Path Telemetry Overhead** | Reviewer demands unguarded debug logging or per-iteration spans inside hot-path loops or stream pipelines. | **GATE FOR REFINEMENT**: Demand log-level guards (`isDebugEnabled()`) or batch-level span amortization. |
| **Ad-Hoc Configuration & Runtime Shim Bloat** | Reviewer proposes runtime dual-format config loaders, wrapper adapters, or permissive schema flags (`.passthrough()`, `extra = 'allow'`). | **GATE FOR REFINEMENT**: Demand canonical config schema parser and preparatory modernization ($S$) of configs and test fixtures. |
| **Ad-Hoc Z-Index Escalation** | Remediation prescribes arbitrary numeric z-indices (`z-index: 9999`) without design system elevation tokens. | **GATE FOR REFINEMENT**: Demand verified design system elevation tokens (`--zIndex-*`) or `isolation: isolate`. |
| **Monolithic Acceptance Criteria Bloat** | Remediation bundles multiple interactive states, viewports, or flows into compound sentences not verifiable by a single independent test. | **GATE FOR REFINEMENT**: Demand decomposition into atomic Given-When-Then criteria or a structured state matrix. |
| **Propagation Suppression** | Remediation prescribes `event.stopPropagation()` / `stopImmediatePropagation()`, OR prescribes `event.preventDefault()` on native checkboxes, radio inputs, links, or submit buttons where it cancels native browser behavior. | **GATE FOR REFINEMENT**: Demand parent target filtering (`event.target.closest('button, a, input, [role="button"]')`) or preventable event contracts on custom non-native buttons. |
| **Post-Render Focus Hacks** | Remediation mandates post-render DOM re-querying (`querySelector`) or `setTimeout` focus restoration after list updates. | **GATE FOR REFINEMENT**: Demand stable entity keys (`key={id}`), DOM node retention, and WAI-ARIA roving `tabindex` state machines. |
| **Callee Masking / Downstream Patching** | Reviewer patches an internal helper/leaf callee where an edge case manifests instead of tracing upstream to the ingress boundary. | **GATE FOR REFINEMENT**: Demand tracing data flow upstream (WHY not just WHERE) to place validation at the highest ingress boundary/caller. |
| **False-Positive Upstream Unreadiness** | Reviewer fails readiness for missing files/methods explicitly assigned to an `Upstream` (`Unimplemented`) DA. | **GATE FOR REMOVAL**: Demand removal in `<Role>_Gated_Issues.md`. |
| **Premature Downstream Coupling** | Reviewer demands implementing features or types belonging to a `Downstream` DA inside the target DA. | **GATE FOR REMOVAL**: Demand removal in `<Role>_Gated_Issues.md`. |
| **Speculative Over-Engineering** | Demands premature optimization, unnecessary abstractions, or unrequested features. (*Protection Exception: Parameter Seams, Governance Decoupling, Placement Altitude, and Scale Invariance MUST be accepted*). | **GATE FOR REMOVAL**: Demand removal in `<Role>_Gated_Issues.md`. |
| **Speculative Collection Complexity** | Demands heavy tree structures (Tries, Red-Black trees) on tiny, fixed-size lists where linear arrays are optimal. | **GATE FOR REMOVAL**: Demand removal per Principle 20. |
| **Subjective Complexity Splitting** | Demands splitting a cohesive function/module solely for line count or nesting without separating mixed concerns, isolating failure domains, or creating a testable seam. | **GATE FOR REMOVAL**: Reject per Principle 17. |
| **Pedantic / Stylistic Preference** | Requests rephrasing, renaming, or cosmetic micro-copy adjustments without functional impact. | **GATE FOR REMOVAL**: Demand removal or reclassify to non-blocking Suggestion. |
| **Spec-Induced Regression** | Demands strict exceptions on external ingress/decode paths that break active codebase behavior or existing unit tests without user request. | **GATE FOR REMOVAL**: Demand removal in `<Role>_Gated_Issues.md`. |
| **Obvious Implementation Signal** | Critiques compiler/syntax trivia or errors whose generalized fix is obvious across all instances from the immediate error signal (fails Miss-Probability Gate). | **GATE FOR RECLASSIFICATION TO SUGGESTION / REMOVAL**: Demand reclassification to Suggestion or removal. |
| **False-Positive Continuous Phasing Demand** | Demands vertical UI-to-DB slicing or 24/7 expand-contract dual-write shims for `NON_CONTINUOUS_OPERATION` (`!NC`) or `NON_CONTINUOUS_INTERMEDIATE` (`!NC0`/`!NCI`). | **GATE FOR REMOVAL**: Reject per Principle 22. |
| **False-Positive Intermediate Boot Demand** | Demands full system cutovers, application bootability, GUI rendering, or migration runners for `NON_CONTINUOUS_INTERMEDIATE` (`!NC0`/`!NCI`). | **GATE FOR REMOVAL**: Reject per Principle 22. |
| **False-Positive Plan Decomposition** | Demands decomposing a single cohesive deliverable (verifiable by a single test run) into a multi-file PRD and ticket suite. | **GATE FOR REMOVAL**: Reject per Principle 23. |
| **False-Positive Application Rule on Library/SDK** | Reviewer demands process signal handlers (`SIGTERM`/`SIGINT`), `process.exit()`, `/healthz` probes, global `TracerProvider` registration, or direct `stdout`/`stderr` logging inside a reusable Library or SDK. | **GATE FOR REMOVAL**: Reject per Principle 24. |

## 3. Reviewer Trade-Off & Conflict Resolution Precedence

When reviewer remediations conflict (either intra-tier in Step 4 or cross-tier), resolve using this strict precedence order:
1. **Correctness, Zero-Data-Loss Migration & Security over Premature Optimization**: Structural test seams, authz/RLS boundaries, and transactional/migration safety take priority over premature caching or micro-optimizations.
2. **Observability Context over Opaque Micro-Savings**: Error `cause` chaining and trace context propagation take priority over micro-benchmarked CPU cycle savings (while enforcing `isDebugEnabled()` guards in hot loops).
3. **Protected Structural Seams vs. Speculation**: Reject speculative abstractions, but ALWAYS preserve **End-to-End Parameter Seams** (`options` injection), **Orthogonal Governance Decoupling**, **Placement Altitude** (`src/utils/`), and **Scale Invariance**.
4. **GUI Layout Stability vs. Accessibility & Loading States**: Follow the Universal 3-tier precedence: (1) `Context.md` user directives > (2) existing codebase conventions > (3) defaults: smooth accordion transitions for empty dynamic slots (preserving error recovery controls in `catch` blocks), top progress lines/inline spinners over heavy skeleton blocks on fast $<200\text{ms}$ desktop loads, ephemeral Toast-based Undo for reversible soft-deletes, `aria-disabled="true"` over native `disabled` on focused async controls, and vector SVG icons over raw emojis.
5. **Transactional Safety over Optimistic UI**: Reject optimistic UI on destructive or irreversible operations (file deletions, binary overwrites, schema migrations).
6. **Startup Migration Runners & Preparatory Modernization ($S \to B$) over Runtime Shims**: Achieve zero data loss and config compatibility via startup migration runners ($V_1 \to V_2$) and preparatory modernization steps ($S$), never via runtime property sniffing or dual-format loaders in domain/UI code.
7. **Browser-Safe Event Coordination over `stopPropagation()`**: Preserve event bubbling to `document` listeners via parent target filtering (`event.target.closest(...)`) when children include native checkboxes/links/submit buttons, or `event.preventDefault()` on custom non-native buttons.
8. **DOM Identity & Roving Tabindex over Post-Render Focus Hacks**: Achieve focus stability via stable entity keys (`key={id}`) and WAI-ARIA roving `tabindex`, never via post-render `setTimeout` DOM queries.
9. **Upstream Ingress Parsing over Downstream Callee Masking**: Block invalid inputs at the highest viable ingress boundary rather than adding defensive null-guards inside internal leaf helpers.
