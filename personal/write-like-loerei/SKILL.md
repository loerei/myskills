# Write Like Loerei

Write public communications, forum posts, release announcements, and community messages in Loerei's distinctive understated, human voice.

## Directives

1. **Zero Exclamation Marks**: NEVER use exclamation marks (`!`). Use plain periods (`.`). Keep the emotional tone calm, grounded, and low-key.
2. **Natural Opening**: Start casually (e.g. `Hi people.`, `Hi everyone.`) without corporate greetings, enthusiasm inflation, or formal introductions.
3. **No Marketing Fluff or Hype**: NEVER use AI buzzwords or promotional adjectives (`seamless`, `robust`, `powerful`, `ultra-fast`, `crisp`, `fantastic`, `revolutionary`, `flawless`). State what the tool does plainly with concrete, modest verbs.
4. **User-First Filtering (Anti-Trivium)**:
   - Cut out backend implementation flexes and developer trivia that the reader does not need to know.
   - Do NOT list table-stakes features that are obvious or expected from any tool in the category.
   - Highlight only the actual problems solved or unique capabilities.
5. **Authentic Indie Dev Empathy**: Speak peer-to-peer with dry, honest self-awareness (e.g. acknowledging unorganized folders, false positives, or bugs pragmatically).
6. **Spare & Readable Layout**: Keep sentences short, paragraphs compact, and bullet points punchy. Avoid wall-of-text formatting.

---

## Negative Constraints (What to Avoid)

| Bad (AI / Corporate Style) | Good (Loerei Style) |
| :--- | :--- |
| `Revolutionary and lightning-fast game launcher!` | `A minimalist game library for your games.` |
| `We have seamlessly integrated advanced Wine and Proton compatibility pipelines!` | `Works out of the box on Windows and Linux (.AppImage).` |
| `Enjoy a cleaner desktop and have a wonderful day!` | `Let me know what you guys think, and enjoy a cleaner desktop.` |
| `Our state-of-the-art icon engine extracts crisp 256x256 graphics!` | *(Cut entirely — table stakes)* |

---

## Workflow

1. **Intake Draft or Feature List**: Review the target message or release notes.
2. **Filter Information**: Drop developer trivia, internal architecture details, and obvious table-stakes features. Keep only what directly benefits the reader.
3. **Apply Voice Constraints**: Strip all hype words, strip all exclamation marks, apply casual plain English phrasing.
4. **Review & Finalize**: Ensure the tone reads like a real human indie developer sharing a practical project.
